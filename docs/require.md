# **【仕様書】ハンバーガーUI・AIタスク細分化アプリ**

### **1\. 概要と選択課題**

* **課題・目的**: ユーザーが入力した大きなタスク（親タスク）を、AI（Gemini API）が実行可能な小さなタスク（子タスク）に自動細分化し、それをハンバーガーの具材に見立てて消化していくタスク管理アプリケーションの開発。  
* **コアバリュー**: ゲーミフィケーション（具材が積まれる視覚的フィードバックと、完了時の「食べる」アニメーション）と、音声入力による登録の簡略化を組み合わせ、タスク実行の心理的ハードルを劇的に下げること。

### **2\. デザイン（UI/UX）**

* **デザインツール**: UIコンポーネントおよびレイアウト設計には **Stitch** を積極的に活用し、一貫した2Dポップテイストを担保する。  
* **画面構成/UI要素**:  
  * **メインダッシュボード**:  
    * 画面中央に「下のバンズ」が常時配置される。  
    * 画面上部に親タスク名が記載された「上のバンズ」が浮かんでいる状態。  
  * **音声入力インターフェース**:  
    * 画面下部に配置された目立つマイクアイコンボタン（長押しまたはタップで録音開始/停止）。  
  * **タスク（具材）リスト**:  
    * 画面サイドまたは下部に、AIが細分化した未完了の子タスク（レタス、トマト、チーズ、パティなどのアイコン付き）がリスト表示される。  
  * **アニメーション要素**:  
    * 子タスク完了時：リストから具材が飛び、下のバンズの上に積み重なるポップなアニメーション。  
    * 親タスク完了時：上のバンズが降りてきてハンバーガーが完成し、キャラクターまたはエフェクトによって「食べられる」完了アニメーション（パーティクルエフェクト等を使用）。

### **3\. 機能要件（Functional Requirements）**

* **\[機能1\] 音声およびテキストでのタスク入力**: Web Speech API（またはGoogle Cloud Speech-to-Text）を利用し、ユーザーの音声をテキストに変換して親タスクとして登録する。手動テキスト入力もフォールバックとしてサポートする。  
* **\[機能2\] AIによるタスク自動細分化**: Gemini APIを活用し、入力された親タスクの文字列から、3〜5個程度の具体的なアクション（子タスク）を生成し、それぞれに「ハンバーガーの具材タイプ」をランダムまたは論理的に割り当てる。  
* **\[機能3\] タスク進捗とUIの連動**: 子タスクのステータス（未完了/完了）を管理する。完了アクションをトリガーとして、対応する具材のDOM要素をハンバーガーのスタック（積み上げエリア）に追加・レンダリングする。  
* **\[機能4\] 完了判定とフィードバック処理**: 全ての子タスクが完了（completed \=== true）になった状態を検知し、自動的に親タスク（上のバンズ）をスタックに乗せ、完了の「食べる」アニメーションを発火させる。

### **4\. 非機能要件（Non-functional Requirements）**

* **パフォーマンス**:  
  * Gemini APIによるタスク細分化のレスポンスタイムは最大でも3秒以内を目標とし、ローディング中は専用のスケルトンUIまたはスピナーを表示する。  
  * 2Dアニメーションはブラウザのレンダリングを最適化（CSSアニメーションやFramer Motion等のライブラリを利用）し、60fpsを維持する。  
* **スケーラビリティ/可用性**:  
  * Google Cloud（Cloud Run等を想定）上でコンテナ化されたNext.jsアプリケーションとしてデプロイし、トラフィックに応じたオートスケールを実現する。  
* **セキュリティ**:  
  * Gemini APIキーやGoogle Cloudのクレデンシャルは環境変数で厳密に管理し、クライアントサイド（ブラウザ）には絶対に露出させない（Next.jsのAPI Routes / Server Actionsでプロキシする）。

### **5\. 技術仕様（UML / データベース / API）**

sequenceDiagram  
    autonumber  
    actor User  
    participant Frontend as Next.js (Client)  
    participant Backend as Next.js (Server Actions/API)  
    participant Gemini as Gemini API

    User-\>\>Frontend: 音声入力で親タスクを指示  
    Frontend-\>\>Frontend: Web Speech APIでテキスト化  
    Frontend-\>\>Backend: 親タスク送信 (POST /api/tasks/decompose)  
    Backend-\>\>Gemini: プロンプト送信（タスク細分化＋具材割当）  
    Gemini--\>\>Backend: JSONレスポンス（子タスクの配列）  
    Backend--\>\>Frontend: 子タスク一覧と具材データを返却  
    Frontend-\>\>User: UI更新（未完了タスクと上下バンズの表示）  
      
    User-\>\>Frontend: 子タスクを完了（タップ）  
    Frontend-\>\>Frontend: 具材積み上げアニメーション実行  
      
    opt 全子タスク完了時  
        Frontend-\>\>Frontend: 上のバンズ合体 & 「食べる」アニメーション再生  
    end

* **主要エンドポイント (Next.js API Routes)**:  
  * POST /api/tasks/decompose: リクエストボディに親タスクの文字列を受け取り、Gemini APIを叩いて細分化された子タスクオブジェクトの配列（各タスク名、具材タイプID等）をJSONで返す。

### **6\. テストケース（Test Cases）**

* **TC-01**: \[音声認識テスト\] \- マイクボタンを押下して発話した内容が、正しくテキスト入力欄に反映されること。  
* **TC-02**: \[AI細分化テスト\] \- 「確定申告を終わらせる」等の親タスクを入力し、Gemini APIから「領収書をまとめる(レタス)」「システムに入力する(パティ)」等の3個以上の子タスクがJSONとして返却され、画面に表示されること。  
* **TC-03**: \[UIインタラクションテスト\] \- 子タスクのチェックボックスをオンにすると、対象の具材が下のバンズの上にアニメーション付きで配置されること。  
* **TC-04**: \[完了アニメーションテスト\] \- 最後の子タスクを完了した際、自動的に上のバンズが乗ってハンバーガーが完成し、数秒後に「食べる」アニメーションが正常に再生されること。
